6. WHERE vs HAVING — and the order SQL really thinks in
=======================================================

  SQL:
    SELECT AccountType, COUNT(*) AS Accounts, SUM(Balance) AS Total
    FROM Accounts
    WHERE Balance > 0
    GROUP BY AccountType
    HAVING SUM(Balance) > 2000
    ORDER BY Total DESC
  Result:
  AccountType | Accounts | Total  
  ------------+----------+--------
  Savings     | 2        | 4700.00
  (1 row)

Logical order: FROM (with its JOINs) -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY (then TOP).
It is the order to REASON in; SQL Server may run the steps differently inside, but the answer is the same.

  SQL:
    SELECT AccountType
    FROM Accounts
    WHERE SUM(Balance) > 2000
    GROUP BY AccountType
  Result:
  SQL Server refused it (error 147): An aggregate may not appear in the WHERE clause unless it is in a subquery contained in a HAVING clause or a select list, and the column being aggregated is an outer reference.

  SQL:
    SELECT AccountType, SUM(Balance) AS Total
    FROM Accounts
    WHERE Total > 2000
    GROUP BY AccountType
  Result:
  SQL Server refused it (error 207): Invalid column name 'Total'.
