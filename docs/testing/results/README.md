# Test result reports

One markdown file per run, named `<short commit>-<hostname>.md` (no dates in file names — repo rule; the date is inside the file), **generated by the runner** (`tests/e2e/run-e2e.sh` / `run-e2e.ps1`).
A second run on the same commit and host overwrites the file — rename the first one (for example `24b82ec-vm-run1.md`) if you want to keep it.

Each report contains: commit, dotnet/node versions, whether `DOTNET_ROLL_FORWARD=Major` had to be used (then it is **not** a net9 result),
the SQL Server version (set `E2E_SQL_VERSION` before the run, or edit the header line afterwards), totals, and one row per check.

Rules
- Commit the report with your session's other changes; it contains no secrets (the runner never writes the connection string). Re-read it before committing.
- A report with SKIP rows is fine; a report that hides them is not. [`../status.md`](../status.md) must say what the SKIPs mean.
- Raw outputs and diffs of the run live in `tests/e2e/actual/` (git-ignored); copy the relevant lines into the report or `status.md` when you describe a finding.
- Manual checks (browser, Docker stack, diagrams) are not in the generated table: add them below it using [`TEMPLATE.md`](TEMPLATE.md).
