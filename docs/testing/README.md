# Testing against a real SQL Server — START HERE

> **If you are a session (human or AI) asked to test, verify, or "run everything" on a machine that has SQL Server —
> or can run Docker — read this page, then follow [`runbook.md`](runbook.md). You do not need the chat history.**

## Why this exists
The 28 topics were built and checked in a sandbox that had **only** a throwaway SQL Server 2022 in Docker and **only a .NET 10
runtime** (the projects target `net9.0`). Nothing has been run against the owner's own SQL Server. This folder is the kit that
lets any later session close that gap repeatably, record what happened, and fix what differs.

## The kit (everything already exists in the repo)

## Which situation are you in?
| You have | Do this |
|---|---|
| A SQL Server you may create databases on (any edition ≥ 2019), or Docker | **Full run** — [`runbook.md`](runbook.md) from step 1 |
| A server where you may NOT create databases | Ask a DBA to run `sql/00-create-lesson-databases.sql` once, then a full run |
| No SQL Server and no Docker | `tests/e2e/run-e2e.sh --no-sql` (runs the 13 lessons that need no database, the frontend tests, the build) and report the rest as **SKIP** — never as PASS |
| Only a failing result to fix | [`triage-guide.md`](triage-guide.md) |

## The 30-second version
```bash
# 1. a SQL Server you can create databases on (Docker one-liner if you have none):
docker run -d --name sql -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='<Strong#Passw0rd>' -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest
# 2. tell the repo where it is (never commit this):
export BTAL_SQLSERVER='Server=localhost,1433;User Id=sa;Password=<Strong#Passw0rd>;TrustServerCertificate=True;Initial Catalog=BasicToAdvancedLearning'
# 3. run everything (≈2 minutes) — Windows: pwsh tests/e2e/run-e2e.ps1
tests/e2e/run-e2e.sh
# 4. read the report it prints (docs/testing/results/<commit>-<host>.md), triage any DIFF/FAIL, update status.md, commit
```

## Ground rules for every testing session
1. **Honesty over green.** A check that was not run is `SKIP`, never `PASS`. Write what you could not verify into `status.md`.
2. **Never weaken a test to get green.** Do not edit a golden file, a script or a lesson just to make a diff disappear — follow [`triage-guide.md`](triage-guide.md).
3. **Real output wins over comments.** If the real server contradicts a lesson comment or diagram, the lesson/diagram is wrong: fix it (and its diagrams) — students must never be misled.
4. **Secrets stay out of git.** The connection string lives only in the environment variable `BTAL_SQLSERVER`; never paste it into a file, report or commit message.
5. **Protected files** (`CLAUDE.md`, `docs/rules/**`, `docs/aidlc.md`, `docs/decisions.md`, `scripts/*.ps1`) are changed only when the owner asks, in their own `rules:` commit — see [`../rules/governance.md`](../rules/governance.md). Propose changes in `docs/review-recommendations.md` instead.
6. **Leave the repo ready for the next session:** result report committed, [`status.md`](status.md) updated, open findings written down (as a list in `status.md`, or as new items in `docs/review-recommendations.md`).
